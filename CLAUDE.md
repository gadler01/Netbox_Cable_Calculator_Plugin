Guidance for Claude Code when working in this repo. See README.md for install and user-facing docs.

## What this is

A NetBox 4.x plugin (`netbox_cable_calc`) that calculates cable lengths for datacenter moves. It has a Django backend and a React frontend, served at `/plugins/cable-calc/`.

## Layout

- `netbox_cable_calc/__init__.py`: plugin config and default settings (aisle width, overheads, bridge length, slack).
- `netbox_cable_calc/views.py`: all backend logic (rack index, length math, bridge routing, BOM, layout files, permissions, API views).
- `netbox_cable_calc/urls.py`: routes `""` (page), `bom/`, `layout/`, `racks/`, `devices/`.
- `netbox_cable_calc/templates/netbox_cable_calc/calculator.html`: injects `window.NETBOX_*` data (including the CSRF token) and loads the bundle and `calculator.css`. Holds the `?v=N` cache-busters for both.
- `netbox_cable_calc/static/netbox_cable_calc/`: `calculator.bundle.js` (built from `ui/`, never edit by hand) and `calculator.css` (edit directly).
- `netbox_cable_calc/layouts/`: saved floor plans and BOM caches written at runtime (`site_{id}.json`, `site_{id}_loc_{id}.json`, `*_bom_cache.json`). Gitignored, so never commit them.
- `ui/src/`: React source.
  - `App.jsx`: main component, scope (site/location) state, tabs, save/load wiring.
  - `FloorPlan.jsx`: single-location floor plan editor.
  - `SiteLayout.jsx`: site-wide view with cross-location bridges.
  - `floorplan.js`: helpers (auto layout, `loadFromServer`, `saveToServer`, `csrfToken`, sessionStorage, bridge helpers, browser routing `shortestPath`).
- `e2e/`: headless browser checks (see below).
- `build/` and `*.egg-info/` are generated by installs. They're gitignored and untracked (since `b23d358`), so edit only the files under `netbox_cable_calc/`.

## Build and deploy workflow

1. Edit `ui/src/*`.
1a. For styling, edit `calculator.css` and bump its own `?v=N` in `calculator.html`. Backend-only changes (`views.py`, `__init__.py`) skip steps 2 and 3.
2. Build: `cd ui && npm run build`. This writes `netbox_cable_calc/static/netbox_cable_calc/calculator.bundle.js`.
3. Bump the cache-buster `?v=N` in `calculator.html` so browsers pick up the new bundle.
4. Commit the source, the bundle and the template together. The bundle is committed on purpose, because NetBox hosts usually don't have Node.
5. Deploy to the dev NetBox (see below).

### Dev NetBox on this host (`nbupg`)

NetBox does **not** run from `~/nbcc`. It runs an editable install of `/opt/netbox/netbox_cable_calc_repo`, a separate git checkout that tracks `origin/development`. It serves the bundle from `STATIC_ROOT` (`/opt/netbox/netbox/static/`), not from the plugin folder.

To deploy, commit and push from `~/nbcc`, then:

```bash
cd /opt/netbox/netbox_cable_calc_repo && git pull
cd /opt/netbox/netbox && sudo -u netbox /opt/netbox/venv/bin/python manage.py collectstatic --no-input
sudo systemctl restart netbox netbox-rq
```

- Don't copy files into the deploy checkout by hand. Local changes there make the next `git pull` fail.
- Compiled `.pyc` files are no longer tracked (`ca7bbff`), so NetBox rewriting them no longer blocks pulls.
- After a deploy that changes routing or length math, delete the `*_bom_cache.json` files in the live layouts folder (use the literal path) so the BOM tab recalculates.
- `collectstatic` never deletes files. An old unused `calculator.js` is still in `STATIC_ROOT`; `collectstatic --clear` removes it.
- Then run the browser checks below.
- Check: the browser console should show `calculator.bundle.js?v=<current number>`. If it shows an older number, the deploy didn't land.
- The live layout files are in `/opt/netbox/netbox_cable_calc_repo/netbox_cable_calc/layouts/`. They're gitignored, so pulls don't touch them. The copies in `~/nbcc` are stale.

### Browser checks (`e2e/`)

`e2e/check.js` drives the real page on the dev NetBox with headless Chromium (Playwright 1.56, which still supports the server's Node 18). It checks the bundle version, the site and location floor plans, scope switching, the Suite 15 BOM, the missing-bridge flag, CSRF and permissions, that a site the user can't view returns 404, and that there are no errors. Screenshots go to `e2e/out/` (gitignored).

```bash
cd e2e && npm install && node check.js <session-file>
```

- It logs in as `cablecalc-e2e`, a NetBox user with no password. It needs view-only permission on sites, locations, racks, devices and cables (and nothing else), so it can see site 105 but every save is refused. The session file holds that user's `sessionid`; keep it outside the repo. To make a new one:
  `cd /opt/netbox/netbox && sudo -u netbox /opt/netbox/venv/bin/python manage.py shell -c "from django.contrib.auth import get_user_model; from django.test import Client; c=Client(); c.force_login(get_user_model().objects.get(username='cablecalc-e2e')); print(c.cookies['sessionid'].value)" 2>/dev/null | tail -1 > <session-file>`
- The only thing it changes is the BOM cache (it clicks "Calculate all cables"). Save checks post to a site with no racks and an empty length list, so they can't write even if the user gets permissions later.
- Both dropdowns are TomSelect boxes; pick by label, not by position.
- The expected `?v=N` is read from the template, so bumps don't need a script change.

There are no unit tests.

## Key concepts

- **Scope**: site, plus an optional location. It lives in React state as `pendingSite` / `pendingLocation`, and the URL is kept in sync with `history.replaceState`.
- **Site view**: `showSiteLayout` is true when a site is selected, no location is selected, and the site has locations. The layout API then merges the site file with every location file (`_load_scoped_layout`).
- **Row id namespacing**: merged rows get prefixed ids (`site:row-1`, `loc125:row-1`) so they don't collide. `_namespace_layout` is idempotent, so a prefix is never added twice.
- **Site-level file holds bridges only**: saves from the site view write `rows: []`, `rackPositions: {}` and only the cross-location bridges (see `setBridgesAndSave` in App.jsx). Rows and same-location bridges stay in each location's own file. `SiteLayout` hides site-level rows that have no racks; these are leftovers from before the site view existed (Sep 18).

## Known issues / next steps

- **Saves now need NetBox permissions.** Users who aren't superusers need "change rack" (floor plans) and "change cable" (lengths), or their saves are refused.
- **Browser Calculator and server BOM disagree.** `shortestPath` in floorplan.js needs a bridge at every row boundary, or it drops to straight-line distance.
- **The BOM cache doesn't notice NetBox changes.** Edits to racks, devices or cables don't clear it. Use Recalculate.
- **Floor plan save errors are hidden.** `saveToServer` only returns true/false, so a permission error just shows as a failed save. `LayoutApiView` has no server-side logging.
- **The TomSelect handler may be redundant.** It sets `pendingLocation` alongside `handleLocationChange` (`onChange`). React skips the second update when the value is the same, so it's harmless but probably not needed.
- **`layoutReady` is set but never read.** Either wire it up (for example, to disable saving while a layout loads) or remove it.
- **No floor plan for racks that are in a site but not in any location.** The site view is read-only for rows. If those racks need laying out, the site view needs its own row editor.

## Conventions

- Match the existing compact JSX style (short lines, inline `useEffect`s).
- Layout files are plain JSON. Rows need `id`, `x`, `y` and related fields. A missing `y` broke rendering before.
- Commit messages are short and imperative ("Add ...", "Fix ...").
